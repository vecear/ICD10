# 診間工具

## 每次要寄給診間時：跑這一行

```bash
python build/build.py && python tools/pack_for_clinic.py
```

產出 `診間包.zip`（約 2.1 MB），整包寄過去、解壓覆蓋舊資料夾就好——**不用記哪個檔有更新**。
診間電腦只能收信（不能上網下載、不能插隨身碟），而 Gmail 連壓縮檔裡的 `.exe` 都擋
（它看的是內容標頭，改副檔名或分割壓縮都沒用），所以包裡的 AutoHotkey 執行檔是
`certutil` 的 base64 文字，到診間還原一次即可。

打包時會自動擋下三種會害診間白跑一趟的錯誤：

- base64 還原後的 SHA-256 與原始 exe 不符
- zip 裡混進任何會被郵件封鎖的副檔名
- 使用說明教人「改第 N 行」但行號已經偏掉、或還在教人按已經移除的按鈕

包裡有四個檔：`icd10.html`、`AutoHotkey64.ahk`（腳本，故意與執行檔同名所以雙擊 exe
就會載入它）、`AutoHotkey64.txt`（base64 的執行檔）、`使用說明.txt`。

# HIS 熱鍵貼入（`his-paste.ahk`）

把工具選好的 ICD 代碼，用一個熱鍵打進 HIS 的疾病碼欄位。

## 為什麼需要另一支程式

`dist/icd10.html` 跑在 Edge 裡，而 HIS（`診間批價修改作業 [OpoC200]`）是 Windows 原生程式。
瀏覽器的沙箱不允許網頁把鍵盤輸入送進另一個進程的視窗——這是安全邊界，改用擴充功能也一樣繞不過。
所以工具只能把代碼放進剪貼簿，最後一哩要由一支在 OS 層的小程式補上。

## 兩種跑法

**免安裝（診間電腦建議走這條）** —— 醫院電腦通常不給裝軟體，AutoHotkey 的 zip 版
解開只有一個 `AutoHotkey64.exe`（1.2 MB），不寫登錄檔、不需管理員權限：

1. 到 [AutoHotkey v2 releases](https://github.com/AutoHotkey/AutoHotkey/releases) 下載
   `AutoHotkey_2.0.26.zip`，解壓後把 `AutoHotkey64.exe` 放到和 `his-paste.ahk` 同一個資料夾
2. 雙擊 `啟動熱鍵.bat`

`啟動熱鍵.bat` 會優先用同資料夾的 `AutoHotkey64.exe`，找不到才退而找已安裝的 v2，
兩種情況都跑得起來。實測（v2.0.26）：免安裝版跑自我測試 30 項全過，與安裝版沒有差別。

**正式安裝** —— 自己的電腦可以直接裝，裝完就能雙擊 `.ahk` 執行：

```bash
winget install AutoHotkey.AutoHotkey
```

不論哪一種，工作列右下角出現綠色 H 圖示就是在跑了。
要開機自動啟動：`Win+R` 打 `shell:startup`，把 `啟動熱鍵.bat` 的捷徑丟進去。

> AutoHotkey 的執行檔**沒有數位簽章**（官方一直如此），Windows SmartScreen 可能跳
> 「已保護您的電腦」，點「其他資訊」→「仍要執行」。下載後可自行核對 SHA-256 與
> GitHub release API 回報的 `digest` 是否相符。

## 用法

1. 在工具裡選好代碼，按**「複製並貼入 HIS」**（代碼進剪貼簿）
2. 游標點進 HIS 的**疾病碼欄位**
3. 按 **F9** —— 代碼逐一打進去，每碼之後按 Enter

| 熱鍵 | 動作 |
| --- | --- |
| `F9` | 送出剪貼簿裡的所有代碼 |
| `Shift+F9` | 只送第一個代碼 |
| `F10` | 預覽：顯示解析到哪些代碼，**不送出** |
| `Ctrl+Alt+D` | 把工具視窗貼到螢幕右緣、拉到全高、永遠置頂（沒開會自己開） |
| `Ctrl+Alt+T` | 切換目前視窗的永遠置頂 |
| `Ctrl+Alt+F9` | 暫停／恢復（暫停時 F9 交還給原本的程式） |
| `Ctrl+Alt+X` | 結束 |

**HIS 跳出版本對照視窗時**：有些碼（例如 `I10`）在 ICD-10 2014→2023 是一對多，
HIS 會跳出「ICD10 2014延伸2023醫令說明」要醫師滑鼠雙擊選一個。腳本偵測到就暫停，
等你選完、焦點回到原視窗再自動補送剩下的碼。**不會自動代選**——選哪個 2023 碼
是臨床判斷，跳過醫師確認等於用自動化製造申報錯誤。

偵測方式是「焦點還在不在**按下 F9 當下的那個視窗**」（記 hwnd，不比對標題），
所以任何作業畫面都有效，也不限於版本對照視窗——重複碼提醒、確認框一樣擋得住。
若原視窗中途整個消失（畫面被關掉），會立刻停止並提示，不會把剩下的碼
打進不知道哪個程式，也不會空等逾時。

## Ctrl+Alt+D：取代瀏覽器的「置頂」

工具內建的「置頂」用的是 Document Picture-in-Picture，而 Chrome／Edge
[把 PiP 視窗限制在螢幕尺寸的 80%](https://developer.chrome.com/docs/web-platform/document-picture-in-picture)
（Canary 108 起從 50% 放寬到 80%），防止網頁用永遠置頂的視窗蓋滿螢幕把使用者鎖住。
高度拉到一定程度就拉不動，是這個限制造成的，`resizeTo()` 同樣受限，網頁端改不掉。

`Ctrl+Alt+D` 改走一般視窗＋`WinSetAlwaysOnTop`，沒有那個上限。實測（1920×1200）：

| | 寬度 | 高度 |
| --- | --- | --- |
| 瀏覽器「置頂」（PiP） | 可以很窄 | 上限約 960px（螢幕 80%） |
| `Ctrl+Alt+D` | 340px | **1128px**（工作區全高） |

兩個實作細節值得記著：

- **一定要用 Edge 的應用程式模式**（`msedge --app=...`）。一般 Edge 視窗有最小寬度，
  實測縮不進 772px；應用程式模式最窄可到 267px，才進得了窄欄的設計範圍 176–565px。
- **貼齊右緣要用「實際」寬度算 x**，不能用要求的寬度。視窗若縮不到要求值，
  用要求值算出來的 x 會把視窗推出螢幕外（實測 772px 的視窗右緣跑到 2272 > 1920）。

窄視窗不會被誤判成手機版面：[app.js](../src/app.js:31) 的 `resolveLayout()` 在偏好為
`dock` 時直接用 dock，只有偏好 `wide` 才依寬度退回 mobile。所以網頁不需要任何改動。

三種複製格式（每行一碼／逗號分隔／碼＋名稱）都能解析，用哪一種都行。

## 四道安全設計

代碼打錯進 HIS 就是申報錯誤，所以預設偏保守：

1. **一定要按鍵才動作** —— 不監看剪貼簿、不自動送出。焦點跑掉時不會有東西被打出去。
2. **視窗守門（預設關閉）** —— HIS 各作業畫面標題差異很大，綁標題會讓熱鍵在部分
   畫面完全不動作、而診間當下看不出原因，所以預設不檢查。想擋「誤按到別的程式」
   再把 `CHECK_WINDOW` 設 `true`。
3. **代碼清單守門** —— 剪貼簿每一行都必須「以代碼開頭，後面接行尾、逗號或中文病名」。
   複製到的若是病歷段落（`T12 compression fracture`、`B12 deficiency`、`A1C 7.2%`）一律拒絕；
   這些寫法本身就長得像 ICD 代碼，只看行首擋不掉。
4. **F10 預覽** —— 不確定剪貼簿裡是什麼，先按 F10 看解析結果。

## 要調的地方（直接改 `his-paste.ahk` 開頭）

| 變數 | 預設 | 什麼時候要改 |
| --- | --- | --- |
| `CHECK_WINDOW` | `false` | 設 `true` 才檢查視窗標題（只擋誤按，代價是換畫面會失效） |
| `TARGET_WIN` | `"OpoC200"` | 只在 `CHECK_WINDOW` 為 `true` 時有作用；跳窗偵測**不看**它 |
| `SEND_ENTER` | `true` | HIS 不需要 Enter 就會帶出病名時設 `false` |
| `CODE_DELAY` | `250` | HIS 反應慢、後面幾碼被吃掉時調大 |
| `KEY_DELAY` | `25` | 打字漏字元時調大（舊系統常見） |

## 驗證狀態

**已實測**（AutoHotkey v2.0.26，語法檢查＋30 項自我測試連續三輪全過）：

- 代碼解析：全庫 96,802 個代碼都解析得到；工具三種複製格式的**實際剪貼簿內容**
  （含 Windows 的 `\r\n` 正規化）解析結果與清單一字不差；重複碼會去重。
- 守門：`T12 compression fracture`、`B12 deficiency`、`A1C 7.2%`、`hematuria was noted on 8/10`
  等取自 HIS 畫面的病歷文字全部被擋下；碼＋中文病名的格式仍放行。
- 端到端（用自建的 GUI 輸入框當 HIS 替身）：視窗標題不符時一個字都不送、
  標題相符時兩個代碼都打得進去且每碼之後換行、`Shift+F9` 只送第一碼、
  剪貼簿是病歷文字或沒有代碼時都不送出。
- **跨進程**：另外跑一輪「還原 exe → 雙擊啟動 → 在替身視窗實際按下 F9」，
  三個代碼（`I10`／`E11.621`／`Z91.148`）逐字正確、每碼之後換行，連續兩輪一致。
  這一輪的意義是熱鍵由**另一個進程**接手，與真實使用時的路徑相同。

> 測這條路時踩過一個坑，留給下次：替身視窗讀值讀得太早，會看到 `I10148` 這種
> 殘缺內容，很容易誤判成「送字漏字」而去調 `KEY_DELAY`。實際上字還在送。
> 要等的時間是「字元數 × KEY_DELAY ＋ 碼數 × CODE_DELAY」再加一點餘裕，
> 不是隨手抓個 2 秒。

**免安裝路線的小技巧**：把腳本命名為 `AutoHotkey64.ahk`（與執行檔同名），
雙擊 `AutoHotkey64.exe` 就會自動載入它，不需要參數也不需要 bat。
實測確認：檔名不同名時雙擊只會開 AutoHotkey 自己的視窗，同名才會自動執行。

**還沒驗證的**：真實 HIS（`OpoC200`）上的行為——疾病碼欄位吃不吃
Enter、送字速度要不要調。這些只有在診間電腦才測得到。

第一次使用時請**先按 F10 預覽**確認解析結果，再按 F9 送出，並核對 HIS 帶出來的病名。
