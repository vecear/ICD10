# ICD-10 門診導引

單一離線 HTML 的 ICD-10-CM 選碼工具，為看診當下設計：內科門診／內科急診／外科三種模式、
依身體部位的症狀導向面板、慢性病與感染科常用快選、相關碼連鎖推薦、就診清單一鍵貼入 HIS、
全庫即時搜尋，以及 DM／HTN／LIPID 的**慢病速查**（健保給付規定與臨床治療目標，每條標出處與查證日期）。
整個工具就是 [`dist/icd10.html`](dist/icd10.html) 一個檔案（約 2.2 MB），
免安裝、免網路、零外部請求，可直接放進診間電腦或隨身碟。

## 三種版面

| 版面 | 用途 |
| --- | --- |
| **桌機工作台**（預設） | 全螢幕三欄：左部位、中面板、右就診清單＋HIS 預覽。看診主力版面。 |
| **側掛窄欄** | 壓成一條窄欄貼在螢幕邊，讓 HIS 佔滿其餘空間；按「置頂」可用 Document Picture-in-Picture 把整條窄欄丟進永遠置頂的小視窗，浮在 HIS 上面。 |
| **手機** | 整列式觸控介面（每列 48px）、底部固定清單列與可展開抽屜。 |

桌機兩種版面在**設定 → 桌機版面**切換，選擇會記住。視窗寬度未達 900px 時會自動改用手機
版面（此時設定面板會說明目前生效的是哪一種、以及放寬視窗就會回去），因此在筆電上把視窗
縮成半螢幕也不會變成擠爆的桌機版。

## 使用

用 Edge / Chrome 開啟 [`dist/icd10.html`](dist/icd10.html)。

- **搜尋**：中文（蜂窩）、英文（cellulitis）、代碼前綴（L03 或 E119）皆可；按 Enter 直接加入第一筆。
- **內科導引**：先選內科門診或內科急診，再依身體部位挑主訴、常見相關疾病與評估碼。
- **急診提醒**：「優先排除／提醒評估」僅供醫師複核，不是自動診斷或急診分流；推薦碼需逐一點選才會加入清單。
- **外科導引**：外傷、傷口、膿瘍、疝氣與術後追蹤等常見情境。
- **點任何代碼**加入就診清單，同時跳出相關代碼（臨床關聯＋同類目）供連鎖加選。
- 灰色虛線代碼為類目碼（不可申報），點了不會加入清單。

### 慢病速查（DM／HTN／LIPID）

三顆小按鈕（**DM／HTN／LIPID**）分別叫出該慢性病的**健保給付規定**與**臨床治療目標**，
給不常看慢性病的醫師在看診當下瞄一眼用。位置依版面而異：桌機工作台常駐在 header，
側掛窄欄與手機放在捲動內容區的最上面（兩者的固定版面寸土寸金，見
[`docs/dense-ui-principle.md`](docs/dense-ui-principle.md)）。三種版面的浮層內容與操作完全一致：
面板內另有一排主題分頁可直接互相切換，關閉用關閉鈕、`Esc`，桌機另可點面板以外任一處。
這一排的尾巴還有一顆**血脂**鈕，叫出下一節的給付試算（放這裡而不是 header：176px 的
header 塞不下第四顆鈕，實測會把模式三鈕擠到第二列）。

**這一塊與代碼區塊有一個本質差異，使用時務必記得**：診斷碼可以逐碼比對健保署官方全庫、
錯了建置就失敗；**給付規定沒有任何機器可驗的權威來源**。所以：

- 每一條都把**出處**與**查證日期**直接印在畫面上（不是藏在提示或註腳裡）。
- 帶生效日的條文會依**當天日期**自動只顯示現行版本；已公告但還沒生效的會另外標
  「新版將於 X 日生效」，不會提前套用、也不會藏起來。
- 免責在「設定 → 關於」那一句（三套版面都叫得出來）。面板內原本也有一句，2026-08-26 移除：
  每天開面板的人只有第一次會讀它，在 176px 窄欄裡它擋掉的閱讀空間比提醒價值大。
- 條文依臨床決策順序分組：**能不能開 → 怎麼開 → 別踩雷 → 不給付 → 治療目標**
  （看到異常數值時的實際查閱順序：先看有沒有給付，再看怎麼開，最後才是目標）。
- 條文下方的「補充說明」收合著，點開是例外、依據與容易誤讀的地方。**數字看起來衝突時先點開它**
  ——例如糖尿病指引的血壓目標 <140/90 與高血壓指引的 <130/80 兩者都對，差在量測基準
  （後者是 722 法則的居家血壓）。
- 條文與補充都**一條一行**：依句號與分號斷段（括號內的分號不切），掛項目符號並懸掛縮排，
  換行的續行才不會跟「下一條」長得一樣。行首的短標（「起始門檻：」「篩檢：」）另外標重，
  因為那正是掃視時要找的詞。斷段只切不改字——`splitSentences` 的段落接回去必須逐字等於
  資料檔原文，E2E 直接拿 `textContent` 比對 `chronic_care.json`。
- **主文的短標會提成獨立的抬頭行**，底下所有條件平行掛（`fillSegments` 的 `promoteLead`）。
  多數給付規定的原文是一張**表**，抬頭是表名、每個分號段是一列；把抬頭黏在第一列上等於
  宣告它只管第一條。所以維護 `text` 時請照這個形狀寫：**`抬頭：條件一；條件二`**，
  條件本身若有決策鍵（如 TG 區間）就再寫成 `TG 200–499：須…`，它會被當次級短標標重。
  **補充（`detail`）刻意不提抬頭**——它是散文，同一段裡有好幾個短標（「眼底：…。腎功能：…」），
  提第一個會把後面不相干的段落錯掛到它底下。

### 血脂給付試算

慢病速查那一排（DM／HTN／LIPID）尾巴的 **血脂** 鈕。輸入血脂值與勾選病史，
算出 ASCVD 風險分級、表一的起始門檻與本例達不達標，並附上表二品項的例外門檻。

**為什麼需要它**：LIPID 的給付判定有三個機械步驟特別容易錯，而三個都不需要臨床判斷——
用錯表（表一是主表，表二只適用公告明列「不適用表一」的健保代碼）、極高／非常高風險的
「組合」條件接錯（是「冠狀動脈疾病**合併**什麼」，不是單一條件）、兩張表的風險因子定義混用
（表一 6 項含代謝症候群、HDL-C 女性 < 50；表二 5 項含「或停經者」、HDL-C 男女同為 < 40）。

**兩張表一律都算**。表一是主表，表二在面板上退為次要區塊——但沒有移除，因為公告明列
「不適用表一」的那批代碼含 atorvastatin、rosuvastatin、fenofibrate，常到不能不算。
同一位病人可能表一未達、表二卻符合（或反之），差別只在你要開的品項走哪一張表——
結論不同時面板會明講。判定邏輯是 `logic.js` 的純函式 `lipidCoverage()`，
單元測試在 `tests/logic.test.mjs`（逐級門檻、極高風險的組合條件、兩表風險因子定義的三處差異、
表二的「LDL 或 TC 兩選一」、fibrate 的兩列、以及沒填數值時不下判斷）。

**「複製結果」輸出的是病歷文字，不是計算機報表**：條文寫全名
（「全民健康保險降膽固醇藥物給付規定表一」）、附生效日與版本、把風險分級的臨床依據
與病人數值攤在同一段，並列出該分層的舉證要求。刻意不出現「試算／計算機」字樣——
讀病歷的是審查醫師，寫工具名只會引出多餘的問題。目的是被核刪時證明「當時就符合」。

### CCr 計算機（Cockcroft-Gault）

header 的 **CCr** 鈕（在「日期」右邊）叫出肌酸酐廓清率計算機，供抗生素劑量調整用。
輸入性別、年齡、體重（kg）、肌酸酐（mg/dL），身高（cm）選填。

`CrCl = (140 − 年齡) × 體重 × (女性 ×0.85) / (72 × Cr)`

**體重用哪一個由 BMI 決定**（依 [MDCalc](https://www.mdcalc.com/calc/43/creatinine-clearance-cockcroft-gault-equation)
採用的 Brown et al／Winter et al）：BMI <18.5 用實際體重、18.5–24.9 用理想體重（Devine）、
≥25 用調整體重（理想 + 0.4×(實際 − 理想)）。這一步是劑量最容易錯的地方——同一位病人
用不同體重算可以差到將近兩倍，所以畫面**一律標明主值是用什麼體重算的**，並把實際／理想／
調整三種結果並列；主值只是依 BMI 的一般建議，肌肉量少、截肢、腎功能不穩者仍需醫師自己挑。
沒填身高就只能用實際體重，面板會直說。

計算邏輯是 `logic.js` 的純函式 `creatinineClearance()`，單元測試在 `tests/logic.test.mjs`
（公式、Devine、BMI 分支、調整體重係數、無效輸入一律不回 NaN）。

**免責**：Cockcroft-Gault 估計值，僅適用腎功能穩定者；可能高估 GFR 10–20%，
體重極端時更不準。實際劑量請依藥品仿單與臨床判斷。

### 就診清單

- **排序**：桌機可拖曳換序，也可用 `Alt+↑`／`Alt+↓`；任一版面都能按「主」把該碼設為主診斷（移到第一位）。
- **貼入 HIS**：預覽框顯示的字串就是複製出去的字串，可選每行一碼／逗號分隔／碼＋名稱三種格式；
  剪貼簿被瀏覽器擋下時會跳出可手動全選複製的後備視窗。
- 點清單裡的代碼可單獨複製該碼。
- 清單**不跨診次保留**，重新整理即清空。
- **連 Ctrl+V 都想省掉**：[`tools/his-paste.ahk`](tools/his-paste.ahk) 是一支 AutoHotkey 常駐小程式，
  游標點進 HIS 疾病碼欄位後按 F9 就把代碼逐一打進去。瀏覽器碰不到原生視窗，這一段只能由 OS 層補；
  用法、四道安全守門與可調參數見 [`tools/README.md`](tools/README.md)。

### 調整各區塊高度

區塊之間的細線可以**拖曳**改變上下兩區的高度（滑鼠、觸控都可以；聚焦後用 `↑`／`↓` 也行）：

| 版面 | 可調的分界 |
| --- | --- |
| 桌機工作台 | 中欄的搜尋結果區、右欄的就診清單區 |
| 側掛窄欄 | 部位區、相關疾病區、清單區 |
| 手機 | 相關碼區、清單抽屜 |

高度會分版面各記各的（窄欄調的不會套到工作台），並存在瀏覽器本機。
每個區塊都有最小高度、也不會把其他區塊擠出視野；要復原就按**設定 → 回復預設高度**。

### 常用列（工作台版面）

工作台版面頂端有一條常用列，可一鍵重加常用代碼；側掛窄欄與手機版面空間有限，不顯示這一條。

- **我的最愛**：在就診清單按 ★ 收藏（三種版面都能按），永遠排在常用列最前面。
- **最近使用**：自動記錄最近 8 個用過的代碼。

最愛、最近使用、日夜主題、桌機版面偏好、各區塊高度與複製格式會存在瀏覽器本機（localStorage）；
localStorage 被停用時工具照常運作，只是不跨診次記住。**不會儲存任何病人資料。**

### 全庫延遲載入

開機只載入精選面板（544 個代碼），全庫 96,802 筆（其中可申報葉碼 73,681 筆）在開機後閒置
時或第一次搜尋時才解壓建索引。載入狀態顯示在設定面板底部；全庫還沒好之前搜尋只會回精選
面板的結果，並在結果區明講。

## 瀏覽器需求

- **Edge / Chrome 80 以上**：全庫解壓需要 `DecompressionStream`。版本過舊時精選面板仍可用，
  設定面板會說明全庫無法載入。
- **側掛窄欄的「置頂」需 Edge / Chrome 116 以上**（Document Picture-in-Picture）。不支援或被
  瀏覽器擋下時只會顯示提示，不會進入假的置頂狀態。

## 開發

```bash
python build/fetch_data.py    # 下載健保署官方 xlsx（2023 版，115.05.06 更新）
python build/convert.py       # 轉 data/codes.min.json 與來源 metadata
python build/build.py         # 組裝 dist/icd10.html（內嵌字型與資料，assert_offline 守門）
python build/inventory.py     # 產生 docs/clinical-content-inventory.md（臨床內容驗收清單）

python -m pytest -q           # Python 測試：資料完整性／精選碼／建置／三套版面 E2E
node --test tests/logic.test.mjs tests/state.test.mjs tests/data.test.mjs   # 純邏輯單元測試
```

`tests/conftest.py` 會在測試開始前自動跑一次 `build/build.py`，所以改完 `src/` 直接跑
pytest 即可，測到的一定是最新的 dist。

原始碼在 `src/`，由 `build/build.py` 依序串成單一 HTML：

| 檔案 | 職責 |
| --- | --- |
| `logic.js` | 純函式核心（搜尋、格式化、葉碼判斷），無 DOM |
| `state.js` | 單一 store：狀態、action、localStorage 持久化 |
| `data.js` | 精選內容與全庫索引的存取層、延遲載入 |
| `render-shared.js` | 三套版面共用的 DOM 建構與區塊更新（chip、清單、設定面板…） |
| `render-wide.js` / `render-dock.js` / `render-mobile.js` | 三種版面各自的骨架與更新對照表 |
| `interactions.js` | document 層事件委派（版面重建也不會漏解事件） |
| `app.js` | 啟動、依視窗寬度決定生效版面、把狀態變動轉成區塊重繪 |
| `styles/` | `industry`（設計系統）→ `app`（共用元件）→ `wide` / `dock` / `mobile` |
| `curated/` | 人工整理的面板、快選與相關碼 JSON |
| `curated/chronic_care.json` | 慢病速查的給付規定與治療目標（**不含 ICD 代碼**，維護方式見下節） |

**開發依賴**：Python 3.8+、Node.js 18+、`pip install openpyxl pytest playwright`，另需執行
`python -m playwright install chromium` 安裝 E2E 使用的瀏覽器。

### 維護慢病速查的內容

資料在 [`src/curated/chronic_care.json`](src/curated/chronic_care.json)，檔頭的 `_schema`
就是欄位說明（建置時會剝掉，不進 dist）。結構是 `topics[]`（`dm`／`htn`／`lipid`）→
`sections[]`（`kind`：`target` 臨床治療目標／`coverage` 健保給付規定／`caution` 實務提醒）
→ `items[]`。每條 item：

| 欄位 | 意義 |
| --- | --- |
| `text` | 一行講完的重點，畫面上直接顯示 |
| `detail` | 展開後的補充（例外、依據、容易誤讀之處），可省略 |
| `source` | 出處名稱＋條號＋版本日期。**不可放網址**——`assert_offline()` 會讓建置失敗 |
| `checked` | 本條的查證日期（`YYYY-MM-DD`）。超過 **6 個月**建置時會印醒目警告 |
| `effectiveFrom` / `effectiveTo` | 適用區間，**兩端都含當日**，可省略（省略＝該端無限） |

**改版怎麼寫**：健保署公告換版時，**不要直接改掉舊條文**——給舊版補上
`effectiveTo`（舊制最後一天），新版另開一條帶 `effectiveFrom`（生效日）。這樣公告日到生效日
之間，醫師看到的是現行的舊制＋一則「新版將於 X 日生效」的預告；生效當天自動翻版，
不需要任何人在那天去改檔案。生效日過後可以擇期把過期條文刪掉（它已經不會顯示）。

**定期重查**：`python build/build.py` 會掃所有 `checked` 日期，超過 6 個月
（`build/build.py` 的 `CHRONIC_CHECK_MAX_MONTHS`）就印出逐條警告與門檻日期。
**警告不會讓建置失敗**——過期的規定會誤導醫師，但讓建置失敗等於門診當天沒工具可用，那更糟。
重查健保署當期公告後，更新該條的 `checked`（內容沒變也要更新：那個日期的意思是
「有人在這天確認過」，不是「這天改過」）。

三個主題的 key 在 `src/state.js` 的 `CHRONIC_TOPICS` 另有一份鏡像（狀態層是零 DOM 的純模組，
讀不到資料檔）。兩邊分歧時建置會警告，`tests/test_chronic_care.py` 也會擋。

內嵌成 data: URI，因此完全離線也能正確顯示。兩個字族皆為

## 資料來源與授權

診斷碼資料來自衛福部健保署「2023年中文版ICD-10-CM/PCS(正式版)(115.05.06更新)」官方 Excel，取自[健保署網站](https://www.nhi.gov.tw/ch/lp-3847-1.html)，依《政府資料開放授權條款》使用。轉檔時定點修正了 10 筆原始檔錯字（詳見 `build/convert.py` 的 `TYPO_FIXES`）。

## 免責

**選碼部分**：本工具僅輔助選碼，不構成醫療或申報建議；最終診斷碼以醫師判斷與健保署現行規範為準。
它不做診斷，也不判斷該做什麼——只把醫師已經做好的決定轉換成代碼。

**慢病速查部分**：加入 DM／HTN／LIPID 速查之後，本工具已跨進**臨床參考**的範疇——它會顯示
治療目標數值與健保給付門檻。這一塊必須另外說清楚：

- **不是給付判定**。給付規定逐年修訂、且有品項層級（健保代碼／廠牌）的例外，那一層刻意不收進來。
  能不能申報，一律以**健保署當期公告**為準；有疑義請直接查當期公告或向健保署確認。
- **不是治療處方**。治療目標出自國內外現行指引的一般建議，實際目標必須依個別病人的年齡、共病、
  低血糖風險、預期餘命與偏好調整；指引本身對部分族群刻意不給單一數字。
- **可能過期**。每條都標了出處與查證日期，請看那個日期再決定要不要採信；超過半年未重查的內容，
  建置時會警告維護者，但**已經散出去的 HTML 檔不會自己更新**。
- 使用本工具產生的任何臨床或申報決定，責任仍在使用者。

**CCr 計算機部分**：它算出來的數字會直接影響抗生素劑量，風險與慢病速查同級：

- **公式本身就有誤差**。Cockcroft-Gault 可能高估 GFR 10–20%，在體重極端（過輕、特別是
  肥胖）時更不準，且**只適用腎功能穩定者**——急性腎損傷、透析中、腎功能正在變動的病人不適用。
- **「用哪個體重」是判斷不是計算**。畫面依 BMI 給的主值只是一般建議；肌肉量少、截肢、
  長期臥床、水腫的病人都可能要改用別的體重，所以三種結果一律並列讓醫師自己挑。
- **不是劑量建議**。本工具不查任何藥品的腎功能劑量表；實際劑量請依藥品仿單與臨床判斷。
