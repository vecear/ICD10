# ICD-10 臨床模式與身體部位導引 — 設計規格

- 日期：2026-08-09
- 狀態：使用者已確認急診模式加入「優先排除／紅旗診斷」提醒
- 範圍：單一離線 HTML 的內科急診、內科門診與外科導引

## 1. 目標

把目前「內科／外科」切換改成三個臨床工作模式：

1. **內科急診**：以急性主訴、快速分流與不可漏掉的嚴重診斷為主。
2. **內科門診**：以常見症狀、慢性病、追蹤與檢驗異常為主。
3. **外科**：保留目前外傷、傷口、術後與常見外科處置內容。

內科症狀不再以一長串平面清單呈現，而是先用身體部位篩選，再以緊湊的症狀卡片呈現，降低桌面寬螢幕的空白並縮短看診時的尋找路徑。

## 2. 介面與互動

### 2.1 模式切換

頁首顯示三個 segmented buttons：

內科急診、內科門診、外科

預設為「內科門診」。切換只更新導引面板與快選區，不清除既有就診清單，也不影響全庫搜尋與相關碼連鎖。

### 2.2 身體部位導覽

內科模式顯示可水平捲動的部位按鈕，至少包含：

- 全身／感染
- 神經／頭頸
- 胸肺／心臟
- 腹部／消化
- 泌尿／生殖
- 皮膚／軟組織
- 肌肉骨骼
- 代謝／檢驗（門診模式）

一次顯示一個部位的症狀卡片，桌面版以兩欄排列，窄螢幕改為單欄。外科模式維持既有面板，不顯示內科部位導覽。

### 2.3 症狀卡片

每張卡片分成三層：

- **主訴／症狀碼**：通常是 R-code 或症狀相關碼。
- **常見相關診斷**：常見、可由醫師評估後加入清單的診斷碼。
- **急診優先排除**：只在內科急診顯示；作為提醒，不自動加入清單。

所有 chip 維持既有行為：可申報葉碼可加入清單，類目碼不可加入。點擊任何主訴、相關診斷或紅旗碼後，右側「相關評估碼」立即更新；在手機版必要時將相關區塊捲動到可視範圍。

### 2.4 相關診斷推薦

沿用目前兩層推薦：

1. 人工臨床關聯表。
2. 同前三碼家族的可申報葉碼。

新增症狀卡片的 related 對照資料，讓點擊症狀碼時能顯示該主訴的常見相關診斷。推薦碼不會自動進入清單，避免把鑑別診斷誤當成已確立診斷。

## 3. 資料結構

新增兩份內科導引資料：

- src/curated/internal_emergency.json
- src/curated/internal_outpatient.json

每份資料以部位分組：

~~~json
[
  {
    "name": "胸肺／心臟",
    "panels": [
      {
        "name": "胸痛／心悸",
        "chief": [["R07.9", "胸痛"], ["R00.2", "心悸"]],
        "diagnoses": [["I20.9", "心絞痛"], ["K21.9", "胃食道逆流"]],
        "redFlags": [["I20.9", "心絞痛"]],
        "related": {
          "R07.9": ["I20.9", "K21.9"]
        }
      }
    ]
  }
]
~~~

redFlags 僅限急診資料使用。related 會在建置時驗證所有 key 與 value 都是現行資料中的可申報葉碼。

新增 src/curated/emergency_quick.json 作為急診快選；門診沿用慢性病、感染科與病原體快選；外科沿用外科快選。

現有 symptoms.json 會由兩份按模式、部位重新整理的資料取代，避免保留不再使用的平面症狀清單。

## 4. 臨床內容原則

- 急診優先排除項目只呈現「提醒醫師評估」，不使用「確診」或「應診斷」等措辭。
- 同一症狀同時存在症狀碼與疾病碼時，預設先呈現症狀碼，再呈現常見診斷。
- 不自動加入診斷碼；醫師需逐一點選確認。
- 優先重用目前已通過全庫葉碼驗證的代碼；新增代碼必須由官方資料建置測試驗證。
- 介面保留免責文字，提醒工具不能取代臨床判斷與健保現行規範。

## 5. 建置與測試

建置管線需：

- 載入兩份內科資料與急診快選。
- 驗證 chief、diagnoses、redFlags、related 內的每個代碼都存在且為葉碼。
- 將模式資料以 window.CURATED 內嵌到單一 HTML。

測試需新增：

- Node 邏輯測試：模式資料的相關推薦合併與去重。
- Python curated 驗證：新資料結構、紅旗碼與急診快選皆為可申報葉碼。
- Playwright E2E：
  - 三個模式按鈕與預設模式。
  - 內科急診／門診部位切換。
  - 症狀卡的主訴、相關診斷、紅旗區分。
  - 點擊症狀後右側相關評估碼更新，且不自動加入推薦碼。
  - 外科既有流程不退化。

成功條件：

1. 看診者可在兩次點擊內從模式與部位進入常見症狀。
2. 點擊症狀碼後，相關診斷在同一頁立即可見。
3. 桌面版不再以單一長欄堆疊所有症狀，且手機版仍可操作。
4. 原有搜尋、清單、複製、外科與離線 file:// 流程全部通過。

## 6. 非目標

- 不做病人資料、病歷儲存、個人化常用碼或自動診斷。
- 不做醫療風險分數或急診分流決策。
- 不改變 ICD-10 全庫資料來源與離線交付方式。
