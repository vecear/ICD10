# ICD-10 相關疾病完整化 — 設計規格

- 日期：2026-08-09
- 狀態：使用者已確認「常見疾病完整化＋急診高風險疾病分層」方向
- 範圍：既有內科急診、內科門診症狀導引與點擊後相關碼推薦

## 1. 問題與目標

目前內科症狀卡使用 `diagnoses` 欄位，但內容同時包含疾病碼、症狀碼與評估碼；部分主訴的 `related` 對照也只有少數項目。醫師點擊症狀後，無法穩定看到足夠完整的常見疾病鑑別。

本次要達成：

1. 每個內科症狀卡都能看到清楚分層的常見相關疾病。
2. 點擊主訴／症狀碼後，右側相關區能顯示該主訴的完整疾病清單。
3. 急診不可漏掉的高風險疾病仍與一般常見疾病分開顯示。
4. 相關疾病只提供醫師評估與點選，不自動加入就診清單。
5. 所有新增 ICD-10 代碼都必須通過目前離線官方資料的葉碼驗證。

## 2. 採用方案

### 2.1 資料欄位獨立化

將內科兩份導引資料的 `diagnoses` 改為 `diseases`：

```json
{
  "name": "咳嗽／感冒",
  "chief": [["R05.9", "咳嗽"], ["R05.3", "慢性咳嗽"]],
  "diseases": [
    ["J00", "感冒"],
    ["J06.9", "上呼吸道感染"],
    ["J20.9", "急性支氣管炎"],
    ["J18.9", "肺炎"],
    ["J44.1", "COPD 急性惡化"],
    ["J45.901", "氣喘急性發作"],
    ["J30.9", "過敏性鼻炎"],
    ["K21.9", "胃食道逆流"]
  ],
  "redFlags": [],
  "related": {
    "R05.9": ["J00", "J06.9", "J20.9", "J18.9", "J44.1", "J45.901", "J30.9", "K21.9"]
  }
}
```

欄位責任固定如下：

- `chief`：病人主訴或症狀碼，維持目前可點選加入清單的行為。
- `diseases`：常見疾病與臨床上常見的相關病因；只放疾病／病況碼，不再混入單純症狀碼。
- `redFlags`：僅急診模式使用的優先排除疾病；不是確診結果，也不自動加入清單。
- `related`：每個 `chief` 對應到實際要在右側顯示的相關疾病與紅旗碼，確保點擊不同主訴時可呈現不同且完整的鑑別。

不保留 `diagnoses` 作為第二套來源，避免同一張卡維護兩份容易不一致的疾病清單。

### 2.2 臨床內容層級

每張卡的疾病數量以約 5–8 個為目標；內容依主訴選擇，不以前三碼家族碼大量灌入。右側相關區仍可在人工關聯結果之後接續顯示前三碼家族葉碼，但卡片本身的 `diseases` 與 `related` 必須是人工挑選的臨床清單。

一般模式的卡片順序：

1. 主訴／症狀碼
2. 常見相關疾病

急診模式的卡片順序：

1. 主訴／症狀碼
2. 常見相關疾病
3. 需要優先排除／提醒評估

紅旗與一般疾病不得在同一張卡重複，避免醫師誤以為兩者具有相同優先層級。

### 2.3 點擊與清單行為

- 點擊 `chief`：加入該症狀碼，並在右側列出 `related[chiefCode]`。
- 點擊 `diseases`：只加入被點擊的疾病碼，並依既有流程更新相關區。
- 點擊 `redFlags`：只加入被點擊的紅旗碼；不因它出現在提醒區就自動加入。
- 顯示推薦碼本身不會改變就診清單內容。
- 模式切換不清除既有清單。

## 3. 資料內容範圍

兩份內科資料都要擴充 `diseases` 與每個主訴的 `related`。至少涵蓋目前已有的八個身體部位分區與主要症狀卡；門診增加的「代謝／檢驗」也必須有疾病層。

內容選擇原則：

- 呼吸道症狀：感染、氣喘／COPD、肺炎、過敏與胃食道逆流等常見病因。
- 胸痛／心悸／呼吸困難：心血管、肺部、胃食道與常見功能性病因；急診危險診斷放到 `redFlags`。
- 腹痛／嘔吐／腹瀉／排便異常：感染、發炎、膽胰、腸胃道阻塞、脫水與常見功能性疾病。
- 泌尿症狀／血尿：泌尿道感染、膀胱炎、腎盂腎炎、結石、攝護腺與腎臟疾病。
- 頭痛／頭暈／神經症狀：常見原發性頭痛、前庭疾病、血壓／循環與神經系統疾病；急診危險項目維持分層。
- 皮疹／搔癢：蕁麻疹、皮膚炎、帶狀疱疹、感染與藥物／過敏相關疾病。
- 關節／背頸痛／麻木：退化、痛風、發炎性關節病、神經根病變與周邊神經病變。
- 檢驗異常：糖代謝、甲狀腺、肝腎功能、貧血與蛋白尿等常見臨床問題。

這些是內容覆蓋方向，不把它們當成自動診斷或分流規則。

## 4. 介面變更

- 症狀卡原本的「常見相關診斷」改顯示為「常見相關疾病」。
- 右側推薦區標題改為「常見相關疾病／評估」，讓症狀碼與疾病碼的關係更清楚。
- 保留目前緊湊 chip 佈局、桌面兩欄與手機單欄，不新增 modal、分頁或自動展開全部疾病。
- 急診紅旗區的提醒文字維持「優先排除／提醒評估」，不使用「確診」或「應診斷」。

## 5. 建置與驗證

建置程式需：

- 收集與驗證 `diseases` 內的所有代碼。
- 收集與驗證 `related` 的 key、value，以及 `redFlags` 內的所有代碼。
- 不再依賴內科資料的 `diagnoses` 欄位。
- 保留既有 curated 來源、資料 hash 與單一離線 HTML 建置流程。

自動化測試需涵蓋：

- Python curated schema：每張內科卡都有非空 `diseases`；疾病清單至少 4 個且不與 `chief`、`redFlags` 重複；每個 chief 都有非空 `related`。
- Python build：內嵌資料包含 `diseases` 與新的介面文字。
- Node logic：相關清單合併與去重行為不變。
- Playwright E2E：點擊主訴後可看到多個疾病碼；疾病 chip 可單獨加入；推薦疾病不會自動加入；急診紅旗仍分開顯示。
- 原有搜尋、複製、清單、外科、手機與 `file://` 流程不得退化。

成功條件：

1. 任一內科症狀卡都能直接看到至少四個經驗證的相關疾病碼。
2. 點擊主訴後，右側相關區能顯示該主訴對應的多個疾病碼，而非只有一個症狀或評估碼。
3. 疾病推薦仍需醫師逐一點選，不會自動污染就診清單。
4. 急診一般疾病與優先排除疾病在視覺與資料層級上分開。
5. 完整 Python、Node、Playwright 與離線產物檢查全部通過。

## 6. 非目標

- 不建立自動診斷、鑑別診斷排序、風險分數或急診分流建議。
- 不新增病人資料、病歷儲存、個人化模型或雲端服務。
- 不修改 ICD-10 官方資料來源、版本鎖定與離線交付方式。
- 不重構與本功能無關的外科資料或全庫搜尋邏輯。
